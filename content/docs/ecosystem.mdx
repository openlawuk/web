# Ecosystem

Open Law adapts the Open Banking participant model to legal practice.

| Open Banking | Open Law |
| --- | --- |
| ASPSP (bank) | **LSP** — Legal Service Provider (law firm) |
| TPP | **TPP** — Third Party Provider (legal tech / client app) |
| Technical provider | **TSP** — Technical Service Provider (PMS / API host) |
| Directory + SSAs | Open Law Directory |
| Open Data | Open Law Open Data API |

Clients are **data subjects**, not Directory participants.

## Flow

```
Directory (SSA) → DCR (client_id) → Client authorisation → Read/Write API
```

1. A participant registers software in the Directory (`client-facing` or `firm-facing`).
2. The Directory issues a signed SSA for that software.
3. The TPP uses the SSA in Dynamic Client Registration at a firm TSP.
4. The client authorises access; the TPP calls Read/Write APIs with client-tier scopes.

## Participation models

- **Client-facing** — open marketplace; no firm allowlist for which apps clients may use
- **Firm-facing** — firm-delegation B2B tools

See the specification repository for normative participation-model detail.
